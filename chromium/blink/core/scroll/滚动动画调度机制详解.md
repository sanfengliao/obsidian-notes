# 概述

当调用 `AnimateToOffset()` 时，滚动动画的实际执行需要通过一套精密的调度系统来驱动。这个系统负责：

1. **注册动画源**（RegisterForAnimation）
2. **请求调度**（ScheduleAnimation）
3. **帧同步信号**（vsync → BeginFrame）
4. **服务动画**（ServiceScrollAnimations）
5. **更新与提交**（主线程 Tick 或 GPU 运行）

---

### 第一步：RegisterForAnimation（注册）


**具体实现**（paint_layer_scrollable_area.cc）：

```cpp
void PaintLayerScrollableArea::RegisterForAnimation() {
    if (HasBeenDisposed())
        return;
    if (LocalFrame* frame = GetLayoutBox()->GetFrame()) {
        if (LocalFrameView* frame_view = frame->View())
            frame_view->AddAnimatingScrollableArea(this);
    }
}
```

**含义**：
- 将此 `PaintLayerScrollableArea` 加入当前 `LocalFrameView` 的 `animating_scrollable_areas_` 集合
- 这样，当帧被处理时，该区域的动画会被定期服务

**数据结构**：

```cpp
// local_frame_view.h, line 1187
ScrollableAreaSet animating_scrollable_areas_;

// 定义：使用 HashSet<Member<PaintLayerScrollableArea>> 或类似结构
```

**关键特性**：
- 可以注册多个动画的可滚动区域
- 支持 deregister（注销）
- 防止重复注册

# 第二层：ChromeClient 层

## 2.1 ChromeClientImpl::ScheduleAnimation

```cpp
// chrome_client_impl.cc
void ChromeClientImpl::ScheduleAnimation(const LocalFrameView* frame_view,
                                        base::TimeDelta delay,
                                        bool urgent) {
    LocalFrame& frame = frame_view->GetFrame();
    FrameWidget* widget = frame.GetWidgetForLocalRoot();
    if (widget) {
        widget->RequestAnimationAfterDelay(delay, urgent);
    }
}
```

**参数**：
- `frame_view`：当前帧视图
- `delay`：延迟时间（默认为 0）
- `urgent`：是否紧急（默认为 false）

**关键概念**：

| 概念 | 含义 |
|------|------|
| `ChromeClient` | 抽象接口，代表浏览器实现的回调 |
| `ChromeClientImpl` | 具体实现，连接 Blink 和浏览器主体 |
| `FrameWidget` | 此帧的 Widget（图形窗口管理） |

## 2.2 FrameWidget::RequestAnimationAfterDelay

```cpp
// frame_widget.h (abstract interface)
// 由具体的实现类如 WebFrameWidgetImpl 继承

void RequestAnimationAfterDelay(base::TimeDelta delay, bool urgent);
```

**作用**：
- 若 `delay == 0`：立即请求下一帧
- 若 `delay > 0`：在指定延迟后请求帧
- `urgent == true`：优先级更高

**选项 A：立即帧请求**
```cpp
widget->RequestAnimationAfterDelay(
    base::TimeDelta(),  // 0ms 延迟
    false
);
```

**选项 B：延迟帧请求**
```cpp
widget->RequestAnimationAfterDelay(
    base::Milliseconds(16),  // 16ms 延迟（约一帧）
    false
);
```

# 第四层：BeginFrame 处理流程

## 4.1 BeginFrame 信号

**来源**：DisplayCompositor（Viz）

```cpp
// BeginFrame 消息包含：
struct BeginFrameArgs {
    base::TimeTicks frame_time;      // 此帧的基准时间
    base::TimeTicks deadline;         // 必须完成的时间
    base::TimeDelta interval;         // vsync 间隔（16.67ms 等）
    uint64_t sequence_number;         // 帧序列号
    bool should_include_animation;    // 是否应包含动画
    // ... 其他字段
};
```

## 4.2 BeginFrame 处理管道（Web Rendering Pipeline）

```
vsync 信号到达
    ↓
[1] BeginImplFrame （合成线程）
    ├─ 更新动画时间戳
    ├─ 处理用户输入（滚动等）
    └─ 准备发送 BeginMainFrame
    ↓
[2] BeginMainFrame （主线程）
    ├─ ServiceScrollAnimations() ← 这里执行动画！
    ├─ 运行 requestAnimationFrame 回调
    ├─ 进行样式重计算
    ├─ 布局更新
    └─ 准备 commit
    ↓
[3] Commit （主线程 → 合成线程）
    ├─ 同步 Layer 树
    ├─ 同步属性树
    └─ 准备待激活树（pending tree）
    ↓
[4] Activate （合成线程）
    ├─ 待激活树变为活跃树
    └─ 准备 rasterization
    ↓
[5] Draw （合成线程）
    ├─ 栅格化 tiles
    ├─ 组织合成帧
    └─ 提交给 GPU
    ↓
[6] Display （GPU）
    ├─ 在屏幕上显示
    └─ 发送下一个 vsync
```

# 第五层：服务动画（ServiceScrollAnimations）

## 5.1 何时调用

**发起者**：LocalFrameView

```cpp
// local_frame_view.cc, line 3774
void LocalFrameView::ServiceScrollAnimations(base::TimeTicks start_time) {
    bool can_throttle = CanThrottleRendering();

    if (!can_throttle) {
        // 主滚动区域
        if (ScrollableArea* scrollable_area = GetScrollableArea()) {
            scrollable_area->ServiceScrollAnimations(
                start_time.since_origin().InSecondsF());
        }

        // 复制 animating_scrollable_areas_（因为迭代时可能修改）
        HeapVector<Member<PaintLayerScrollableArea>>
            animating_scrollable_areas_copy(animating_scrollable_areas_);

        for (PaintLayerScrollableArea* scrollable_area :
             animating_scrollable_areas_copy) {
            // ← 核心：调用每个注册的滚动区域的服务方法
            scrollable_area->ServiceScrollAnimations(
                start_time.since_origin().InSecondsF());
        }
    }
}
```

**调用时机**：
- 每个 BeginMainFrame 处理期间
- 帧时间戳来自 BeginFrameArgs
- 不会被限制（即使在后台也会调用）

## 5.2 时间参数

**从 BeginFrameArgs 提取**：

```cpp
base::TimeTicks frame_time = begin_frame_args.frame_time;
    ↓ 转换
double monotonic_time_seconds =
    frame_time.since_origin().InSecondsF();
    ↓ 传递给
ServiceScrollAnimations(monotonic_time_seconds)
```

**意义**：
- 所有动画使用相同的时间戳（一帧内一致）
- 避免时间抖动导致的动画闪烁

# 第七层：TickAnimation 执行

## 7.1 主线程 Tick

```cpp
// programmatic_scroll_animator.cc, line 85-104
void ProgrammaticScrollAnimator::TickAnimation(
    base::TimeTicks monotonic_time) {

    if (run_state_ != RunState::kRunningOnMainThread)
        return;  // 只在主线程运行时处理

    // 第一帧时初始化起始时间
    if (start_time_ == base::TimeTicks())
        start_time_ = monotonic_time;

    // 计算已经历的时间
    base::TimeDelta elapsed_time = monotonic_time - start_time_;

    // 检查是否完成
    bool is_finished =
        (elapsed_time > animation_curve_->Duration());

    // 从曲线获取当前位置
    ScrollOffset offset =
        BlinkOffsetFromCompositorOffset(
            animation_curve_->GetValue(elapsed_time));

    // 立即应用到界面
    ScrollOffsetChanged(offset, GetScrollType(), source_type_);

    if (is_finished) {
        // 动画完成
        run_state_ = RunState::kPostAnimationCleanup;
        AnimationFinished();
    } else if (!scrollable_area_->ScheduleAnimation()) {
        // 调度失败，无法继续
        ResetAnimationState();
    }
}
```

## 7.2 时间线详解

**假设**：
- 滚动从 0 到 500px
- 动画总时长：400ms
- vsync：60Hz（每 16.67ms）

```
帧号  实时(ms)  start_time    elapsed_time    is_finished?    位置(px)
────────────────────────────────────────────────────────────────
 1    0ms      0ms           0ms             ✗              0
 2    16.67ms  0ms           16.67ms         ✗              ~25
 3    33.33ms  0ms           33.33ms         ✗              ~50
 ...
12    183ms    0ms           183ms           ✗              ~250
 ...
24    383ms    0ms           383ms           ✗              ~495
25    400ms    0ms           400ms           ✓              500 ← is_finished = true
26    416.67ms  (清理阶段)   ...             -              (不再调用)
```

# 关键概念详解

## 何为 "RegisterForAnimation"

**名词**：在某个容器中注册（登记）

**实际作用**：
```
animating_scrollable_areas_.insert(this);
```

**效果**：
- 此 PaintLayerScrollableArea 加入动画服务列表
- 每个 BeginMainFrame，都会遍历此列表，逐个调用 ServiceScrollAnimations

**类比**：
```
// 观察者模式的变体
LocalFrameView 维持一个需要更新的元素列表
每帧都对列表中的每个元素说："嘿，该更新你了"
```

## 何为 "ScheduleAnimation"

**动作**：请求浏览器在下一帧被处理

**实际链路**：
```
ScheduleAnimation()
    ↓
ChromeClient (告诉浏览器)
    ↓
FrameWidget (请求下一帧)
    ↓
DisplayCompositor (如果还没有)(请求 vsync)
    ↓
GPU Driver (告诉显示器)
    ↓
（显示器在下一个 vsync 时刻发送中断信号）
    ↓
DisplayCompositor 收到 vsync
    ↓
发送 BeginFrame 消息到 Blink 进程
    ↓
LocalFrame 处理此帧
    ↓
ServiceScrollAnimations() 被调用
```

**支持多次调用**：
```cpp
scrollable_area->ScheduleAnimation();  // 第 1 帧
scrollable_area->ScheduleAnimation();  // 第 2 帧（仍需要）
scrollable_area->ScheduleAnimation();  // 第 3 帧（仍需要）
... 直到返回 false 或不再调用
```

# 失败场景分析

## 场景 1：ScheduleAnimation 返回 false

```cpp
if (!scrollable_area_->ScheduleAnimation()) {
    ResetAnimationState();
    ScrollOffsetChanged(offset, GetScrollType(), source_type);
}
```

**可能原因**：
1. 浏览器标签页在后台
2. 窗口已最小化
3. 元素已被销毁
4. LocalFrameView 已被销毁

**结果**：
- 动画立即停止
- 应用最终位置（缓存的 offset）
- 状态清理

## 场景 2：TickAnimation 调用失败

```cpp
} else if (!scrollable_area_->ScheduleAnimation()) {
    ResetAnimationState();  // 无法继续调度
}
```

**发生时机**：
- 动画运行中，条件改变
- 如 vsync 停止、窗口隐藏等

## 场景 3：多次快速请求

```javascript
element.scrollTo({top: 300, behavior: 'smooth'});
element.scrollTo({top: 500, behavior: 'smooth'});  // 立即调用
```

**处理**：
```
第一个 AnimateToOffset(300)
├─ RegisterForAnimation()  ← 注册一次
└─ ScheduleAnimation()  ← 请求一次

第二个 AnimateToOffset(500)
├─ 旧 on_finish_ 回调被执行（kInterruptedByScroll）
├─ target_offset_ = 500 (覆盖)
├─ 新 animation_curve_ 创建（共享同一注册）
└─ ScheduleAnimation()  ← 再次请求（仍在列表中）
```

**结果**：
- 只需一次 RegisterForAnimation（已在列表中）
- 多次 ScheduleAnimation（但浏览器会合并）
- 状态顺畅过渡

# 性能优化分析

## 1. RegisterForAnimation（一次性）

```cpp
// 仅在第一次调用时添加
animating_scrollable_areas_.insert(this);

// 后续请求复用同一注册
// 不会重复添加（使用 HashSet）
```

**成本**：O(1)

## 2. ScheduleAnimation（每帧可调用）

```cpp
// 简单的指针查询和方法调用
widget->RequestAnimationAfterDelay(delay, urgent);
```

**成本**：O(1)，非常轻

## 3. ServiceScrollAnimations（遍历）

```cpp
for (PaintLayerScrollableArea* scrollable_area :
     animating_scrollable_areas_copy) {
    scrollable_area->ServiceScrollAnimations(monotonic_time);
}
```

**成本**：O(n)，其中 n = 活跃动画区域数
- 通常 n ≤ 10
- 可接受

## 4. TickAnimation（计算）

```cpp
// 每帧执行
base::TimeDelta elapsed_time = monotonic_time - start_time_;
animation_curve_->GetValue(elapsed_time);  // 三次样条求值
```

**成本**：O(1)，数学运算轻量
- **总耗时** ~ 0.1ms （在 16.67ms 预算内分配 1% 级）

# GPU vs 主线程调度差异

## GPU 调度路径

```
GPU 路径：
UpdateCompositorAnimations()
    ↓
AddAnimation(KeyframeModel)
    ↓
发送到合成线程
    ↓
GPU 自行计算每一帧
    ↓
（不再调用 TickAnimation）
    ↓
NotifyCompositorAnimationFinished()
```

**特点**：
- 调度仅一次
- GPU 独立运行
- 无需 ServiceScrollAnimations 服务

## 主线程调度路径

```
主线程路径：
每个 BeginMainFrame
    ↓
ServiceScrollAnimations(frame_time)
    ↓
TickAnimation(frame_time)
    ↓
（每帧计算位置）
    ↓
（需要 ScheduleAnimation 继续请求）
```

**特点**：
- 每帧调用一次
- 需要持续调度
- 依赖 BeginMainFrame 频率

---

# 总结：调度流程的五个关键时刻

| 时刻 | 事件 | 代码位置 | 作用 |
|------|------|----------|------|
| **T0** | ScheduleAnimation 返回 true | programmatic_scroll_animator.cc | 请求下一帧 |
| **T1** | vsync 到达，BeginFrame 消息 | DisplayCompositor | 触发帧处理 |
| **T2** | ServiceScrollAnimations 被调用 | local_frame_view.cc | 遍历动画列表 |
| **T3** | TickAnimation 被调用 | programmatic_scroll_animator.cc | 计算当前位置 |
| **T4** | ScrollOffsetChanged 应用 | programmatic_scroll_animator.cc | 视觉更新 |

这五个时刻形成了一个完整的帧循环，直到动画完成。

```javascript
requestAnimationFrame((timestamp) => {
    // 回调在 BeginMainFrame 时被调用
    // 与 ServiceScrollAnimations 在同一帧
    console.log("我被调用了");
});
```

**相似**：都在 BeginMainFrame 期间
**差异**：
- rAF：用户代码
- ScrollAnimation：浏览器内部动画

## CSS Animation

```css
div {
    animation: slide 0.4s ease-out;
}
@keyframes slide {
    from { transform: translateX(0); }
    to { transform: translateX(500px); }
}
```

**相似**：都使用关键帧动画曲线
**差异**：
- CSS：由浏览器自动管理
- Scroll：由用户 API 触发（element.scrollTo）

## Web Animation API

```javascript
const animation = element.animate(
    [{scrollLeft: 0}, {scrollLeft: 500}],
    {duration: 400, easing: 'ease-out'}
);
```

**相似**：都是用户启动的动画
**差异**：
- WAAPI：通用动画框架
- ScrollAnimation：特化于滚动

这个调度系统的精妙之处在于：
- 🎯 **精确同步**：所有动画使用相同的帧时间戳
- ⚡ **高效路由**：GPU 优先，主线程备选
- 🔄 **自动适配**：根据帧率、设备状态动态调整
- 🛡️ **容错机制**：失败时立即应用，不卡住
