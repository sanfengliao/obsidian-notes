# 00a · 最基础的工具与环境术语（先看这篇）

> 这是真正写给「完全没碰过编程」的人的。
>
> 你要做的第一件事不是写代码，而是**装一堆东西、配环境**。装的时候会冒出来一堆词——node、npm、npx、jdk、Android Studio、Xcode……这篇就是给你解释这些词是什么、为什么要装、装了干嘛用。
>
> 看完这篇，AI 让你「打开终端」「装个 node」「配一下 PATH」时，你不会一脸懵。
>
> *注：下面有些地方用你熟悉的「大模型 / 对话」来类比，方便理解；但只在**真能对得上、且你作为普通使用者就懂**的地方用，对不上的就老老实实讲大白话，不硬套。*

---

## 第一组：跟「打字发指令」有关的

### 命令行 / 终端（Terminal / Command Line / Shell）

**大白话**：一个**黑底白字、靠打字发指令**的窗口。平时你用鼠标点来点去，在终端里是**打字下命令**。

- Mac 上叫「终端 (Terminal)」，Windows 上叫「命令提示符 / PowerShell」，现在更常用的是跨平台的工具。
- AI 经常说「在终端里运行 xxx」，意思就是：打开这个黑窗口，把那行命令敲进去，回车。

**类比**：平时你点按钮，是点别人给你做好的按钮；在终端里你直接打字下命令。就像用 AI 时你**直接打字发 prompt**，而不是点它给的预设按钮——终端就是你**跟电脑打字对话**的窗口，你敲的每行命令就是你说给它听的一句话。

> 你什么时候碰到：几乎每次操作都离不开它。AI 给你的命令（像 `npx create-expo-app myApp`）都要在这里敲。

---

### 路径（Path / 路径）

**大白话**：一个文件或文件夹在电脑里的**地址**。

- **绝对路径**：从硬盘根开始，完整地址。像 `/Users/你/Desktop/myApp`（Mac）或 `C:\Users\你\Desktop\myApp`（Win）。
- **相对路径**：相对于「你当前在哪个文件夹」的地址。像 `./src/App.tsx` 表示「当前文件夹里的 src 里的 App.tsx」。

**类比**：绝对路径像「**北京市海淀区中关村大街 1 号**」——从国家往下，完整地址，谁都找得到。相对路径像「**隔壁那家便利店**」——得先知道**你现在站在哪**，才知道这便利店是哪家。换条街问「隔壁便利店」，指的就不是同一家了。

> 你什么时候碰到：AI 说「进入项目目录」「这个文件在 `src/screens/` 下」时。看不懂路径就不知道文件在哪。

---

### 环境变量 / PATH（最常让你卡住的东西）

**大白话**：电脑有一些**全局的设置项**，其中最重要的一个就叫 **PATH**。

- PATH 告诉电脑：「**当我在终端里敲一个命令时，去哪些文件夹里找对应的程序**」。
- 你装了 node，但终端里敲 `node` 却提示「command not found」——**十有八九就是 node 没被加进 PATH**，电脑不知道去哪找它。

**类比**：PATH 像一份「**电脑认识哪些工具的清单**」。就像你给 AI 配了哪些工具，它就只会用清单里的那些；清单上没有的工具，你让它用，它就说「我不认识这个」。电脑也一样——你装了 node，但没把它登记进 PATH 这份清单，电脑敲 `node` 时就一脸懵：「清单里没这号工具，找不到」。这就是你卡在「command not found」的根因。

> 你什么时候碰到：装完 jdk / node 后，终端报「command not found」或「不是内部或外部命令」。这时跟 AI 说「我装了 xxx 但终端找不到」，AI 会让你「配一下 PATH」。
> 好消息：用 Mac + 现代工具，很多 PATH 是自动配的；用 Expo 的话很多坑也被绕开了。但这个词你得认识。

## 第二组：跟「装基础工具」有关的

### Node / Node.js

**大白话**：一个**让电脑能运行 JavaScript 代码**的程序。

- React Native 的代码是 JavaScript 写的，你电脑得装了 Node 才能跑起来。
- 装了 Node，**自动就带了 npm**（下面讲）。

**类比**：你发一段 prompt 给 AI，得有个**模型**在背后执行它，prompt 才有反应；JS 代码也一样，得有 Node 在背后执行它，代码才跑得起来。**没装 Node，JS 代码发出去没人执行**——就像没选模型，对话发出去没人理你，一点反应没有。

> 你什么时候碰到：搭环境第一步基本就是装 Node。AI 说「确认装了 node」「node 版本多少」时，就是它。

---

### npm

**大白话**：Node 自带的**「代码包商店」**。别人写好的代码包，你用 npm 下载来用。

- **包 / 库（Package / Library）**：别人写好的一段功能代码，打包好供人直接用，省得你自己造轮子。
- 常见命令：
  - `npm install xxx` —— 装一个包（也写作 `npm i xxx`）
  - `npm install` —— 把项目需要的所有包全装上（项目里有个清单文件 `package.json`，它照着装）
  - `npm run xxx` —— 跑项目里定义的某个脚本（比如 `npm run start` 启动项目）

**类比**：npm 上每个「包」就像一个**封装好的 skill（能力包）**——别人把某个能力做好了、打包好，拿来就能用，省得自己从头造。你想要某个功能（比如做图表），就去 npm 上找一个对应的包，`npm install` 把它装进来，这个能力就成了你项目的一部分，随时能调用。

> 你什么时候碰到：AI 说「装个依赖」「`npm install`」时。这是你敲得最多的命令之一。

---

### npx

**大白话**：npm 的**兄弟**，用来「**临时运行某个包里的命令，不用先把它永久装到电脑上**」。

- 经典场景：建一个新 RN（Expo）项目，命令是 `npx create-expo-app myApp`。
  - 意思：临时去拉 `create-expo-app` 这个工具，用它建个项目，用完就算，不留在你电脑上占地方。

**类比**：接上面 skill 的说法——`npm install` 是把某个 skill **永久装进你的能力库**，以后随时能调用；`npx` 是**临时调用一次这个 skill，但不装进能力库**，用完就没了，你的能力列表里不留下它。所以建项目那一步用 `npx`——这个「建项目」的 skill 你只用这一次，没必要永久装着占地方。

> 你什么时候碰到：AI 给你的第一条建项目命令里，多半是 `npx ...` 开头。别被它和 npm 搞混——npx 是「临时调用」。

---

### JDK（Java Development Kit）

**大白话**：开发 Android 必须的一套 **Java 工具包**。因为 Android 系统底层依赖 Java。

- 没 JDK，Android 相关的编译/打包就会报错。
- **版本敏感**：现在 RN 通常用 **JDK 17**。装错版本（太老或太新）可能出问题，AI 让你装哪个版本就装哪个。
- Mac 上推荐用工具装（比如 homebrew），别去官网手动下，省得配 PATH。

**类比**：JDK 就是 **Java 的「执行引擎」**，跟前面 Node 之于 JS 是一回事——Node 让 JS 跑起来，JDK 让 Java 跑起来。你不直接写 Java，但安卓那套打包工具是 Java 写的，背后得有 Java 的执行引擎兜底，否则那套工具直接罢工。

> 你什么时候碰到：跑 Android 模拟器、打包 Android 安装包时，缺 JDK 会报红字错误。AI 看到报错会说「装一下 JDK 17」。

---

### SDK（Software Development Kit）

**大白话**：开发某个平台需要的**工具包**。`Android SDK` = 开发安卓的工具包，`iOS SDK` = 开发苹果的工具包。

- 里面是一堆系统接口、模拟器镜像之类的东西。你写 App 要调用手机的功能（相机、传感器等），得靠 SDK 提供这些接口。

**类比**：SDK 就是**成套的能力包 + 用它提供的接口来调用**。比如要调手机相机、读相册，得装 Android SDK / iOS SDK；要做语音识别，装个语音 SDK；要显示地图，装个地图 SDK——**某一类现成能力，做成一套打包好给你调用**，就是 SDK。

> 💡 **一个容易混的点**：「SDK」「第三方库」「依赖」本质都是**同一类东西**——别人写好的现成代码，拿来直接用，只是不同视角的叫法，不用纠结叫法：
> - **第三方库 / 包**：泛指别人写好的现成代码包，最宽泛（npm 上下的都是）。
> - **依赖**：从「关系」角度说——你的项目**依赖**这些包才能跑，所以叫依赖。一个包可以同时是「第三方库」和「依赖」。
> - **SDK**：偏「**成套的、某一领域的现成能力**」这么叫，比如 Android SDK、语音 SDK、地图 SDK。范围上常比单个库更大更全一点，但本质一样，都是「现成能力，拿来用」。
>
> 一句话：听到任何一个，都理解成「**别人做好的现成能力包，装进来就能用**」就对了。

> 你什么时候碰到：装 Android Studio 时会一起装 Android SDK。AI 说「SDK 没装全」「装个 Android 13 的 SDK」时，就是它。

---

## 第三组：跟「手机平台」有关的

### Android Studio

**大白话**：Google 官方的 **Android 开发大工具箱**（一个软件）。

- 关键认知：**用 RN 开发时，你一般不直接在里面写代码**（代码在 VS Code 里写，见下）。你借 Android Studio 来做两件事：
  1. **装 Android SDK**（安卓开发工具包）
  2. **开 / 管 Android 模拟器**（在电脑上假装一台安卓手机）
- 它体积很大，下载安装要一会儿，别急。

**要点**：Android Studio 本身就是个写代码的软件，但用 RN 开发时，**你不在它里面写代码**（代码在 VS Code 写）。你主要借它干两件事——装 Android SDK、开模拟器。它是「环境 + 模拟器」的场所，不是你写 RN 代码的主场。

> 你什么时候碰到：要预览安卓效果、要打包安卓 App 时。AI 说「打开 Android Studio 建个模拟器」「在 AVD 里开一台 Pixel」时。

---

### Xcode

**大白话**：Apple 官方的 **iOS / macOS 开发大工具箱**。

- **只有 Mac 电脑能装**，Windows 装不了——这是苹果的硬限制。
- 意味着：**想开发 / 打包 iOS 的 App，必须有一台 Mac**。Windows 用户只能开发安卓（除非用 Expo 的云打包，后面提）。
- 用它来：开 iPhone 模拟器、打包 iOS 安装包、签名上架。

**要点**：和 Android Studio 同理，但苹果**把 iOS 开发锁死在 Mac 上**——就像有些软件只能在特定硬件上跑一样，想碰 iOS 就必须用 Mac，没得绕。

> 你什么时候碰到：要预览 iPhone 效果、要打包 iOS App 时。AI 说「在 Xcode 里开模拟器」「用 Xcode 打包」时。
> 如果你只有 Windows：跟 AI 说清楚，它会帮你走「安卓 + Expo」的路线，不折腾 iOS。

---

### 模拟器（Emulator / Simulator）vs 真机（Device）

- **模拟器**：电脑上**假装出来的一台手机**，不用真机就能预览 App。安卓的叫 Emulator，苹果的叫 Simulator。
- **真机**：插上数据线（或无线连接），让 App 跑在你**兜里那台真手机**上。

**要点**：模拟器是电脑上「假装的手机」，方便、快，但和真机有时不一样（比如相机、传感器、性能）；真机才是用户真正会用的环境。所以**开发时用模拟器快出活，上线前一定要在真机上试一遍**，不然可能到用户手机上才暴露问题。

> 你什么时候碰到：AI 说「在模拟器里跑一下」「连真机看看效果」时。开发时主要用模拟器，快出活；最后用真机验收。

---

## 第四组：跟「写代码的地方」有关的

### IDE / 编辑器 / VS Code

- **IDE**（Integrated Development Environment，集成开发环境）：写代码的**大本营软件**，集成了编辑、提示、报错、调试等功能。Android Studio、Xcode 本身就是 IDE。
- **编辑器**：更轻量的写代码工具。**VS Code**（Visual Studio Code）是微软出的、目前最流行的代码编辑器，插件多、轻快。
- 你和 AI 主要在 VS Code 里看代码、改代码。Android Studio / Xcode 多半只用来开模拟器和打包，不用来写 RN 代码。

**要点**：VS Code 就是你**写代码的主软件**，你天天泡在里面改代码、看报错、装插件。Android Studio / Xcode 只是偶尔去用的「专用车间」。

**VS Code 实操（新手必知）**：
- **打开项目**：别双击单个文件，要 `File → Open Folder`（Mac：`文件 → 打开文件夹`），选**整个项目文件夹**。左边「资源管理器」会显示项目所有文件。
- **左边栏（资源管理器）**：项目的文件树，点文件就打开。`android/`、`ios/`、`src/` 这些文件夹都在这浏览。
- **内置终端**：菜单 `Terminal → New Terminal` 打开（快捷键是 Ctrl 加反引号键，反引号在 Tab 上方）。VS Code 里直接开终端，不用单独开终端窗口——你跑命令（`npx expo run:android`、`npm install`）就在这敲。
- **保存**：`Cmd+S`（Mac）/ `Ctrl+S`（Win）。改完一定保存，Metro 才会热刷新。
- **插件（扩展）**：左边栏的方块图标，或 `Ctrl+Shift+X`，搜插件装。CodeBuddy、ESLint、Prettier 都从这里装。

### CodeBuddy（你的 AI 编程助手）

**大白话**：CodeBuddy 是腾讯出的 **AI 编程助手**——就是这份指南里说的「帮你开发 app 的那个 AI」。它有两种用法，选一种即可：
- **CodeBuddy IDE**：腾讯基于 VS Code 魔改的独立软件，VS Code 的界面 + 内置 AI，开箱即用。
- **VS Code 插件**：如果你已装了普通 VS Code，装个 CodeBuddy 插件也行，效果一样。

两种界面、操作基本一致，所以上面说的 VS Code 操作，在 CodeBuddy IDE 里照样适用。

**它干什么**：
- 你用大白话跟它对话提需求（「加个登录页」「这个报错怎么修」），它帮你写代码、改代码、解释代码。
- 它能**直接看到你项目的文件**，不用你手动复制上下文（比普通 ChatGPT 方便）。
- 流程就是：你提需求 → 它写 → 你看效果 → 不对再让它改。

**类比**：CodeBuddy 就像一个坐在你旁边的**程序员助手**——你用大白话说要什么，它帮你写、解释、修 bug，你们俩都在 VS Code 这个「工位」上干活。它本质上就是个 agent（能看你的代码、能动手改），这份指南里说的「用 AI 开发 app」，主角就是它。

> 你什么时候碰到：你朋友开发时，主要就是和 CodeBuddy 对话。AI 说「我来加这段代码」「把那个文件改成 XX」时，就是 CodeBuddy 在干活。

## 第五组：跟「RN 特有」有关的

### Expo（强烈建议零基础用它）

**大白话**：RN 的一套**省心工具链**。原本裸用 RN（叫 **RN CLI**）要自己配 JDK、Android SDK、Xcode 一堆原生环境，很折腾；**Expo 把这些麻烦事都帮你包好了**，开箱即用。

- 装好 Node 就能用 Expo 开发，不用装 Android Studio / Xcode 也能在手机上预览（通过 **Expo Go** 这个 App，扫码就行）。

**类比（核心，记牢这个层级关系）**：
- **RN 本身 = 大模型**：是**核心引擎**，能力都在它身上。但你直接裸用它，底层那一堆麻烦事（JDK、Android SDK、Xcode、原生编译）全得自己一个个配，又累又容易踩坑——就像直接裸调大模型，prompt 工程、工具接入、记忆、编排全得自己从零搭。
- **Expo = agent**：在大模型之上套了一层，把底层那些麻烦事**全封装好**，开箱即用，你只管在上层写应用逻辑，不用操心底层怎么搭——就像 agent 帮你把工具、编排、记忆都封装好了，你只管描述任务。

记住这个层级：**RN（大模型，核心引擎）→ Expo（agent，上层封装，让你用得更省心）**。所以 Expo **不是替代 RN**，而是让 RN 更好用的一层——就像 agent 不替代大模型，而是让大模型更好用。

- 零基础 + AI 协作，**强烈建议用 Expo**：相当于直接用 agent，跳过 80% 自己搭底层的坑。

> 你什么时候碰到：建项目第一条命令就是 `npx create-expo-app myApp`。AI 会默认走 Expo 路线（除非你说要裸 RN）。
> 注意：Expo 也有做不到的极少数功能（要用某些很底层的原生能力时），但对绝大多数 App 足够了。等真碰到再说。

### prebuild：从 Expo 托管「退到底层」

**大白话**：执行 `npx expo prebuild` 会**生成原生的 `android/` 和 `ios/` 文件夹**，让你拿到原生代码的控制权——你朋友走的就是这条路。

- **为什么要 prebuild**：Expo 托管模式省心，但有些事它不让碰——加自定义原生模块、改底层原生配置、用某些 Expo 不支持的原生能力。碰到这些就得 prebuild，把原生层拿出来自己管。

**类比**：Expo 托管时，agent 这层（Expo）帮你把底层麻烦事（原生环境、打包）封装好了；**prebuild = 退出这层封装，把底层接管过来**——失去省心，换来对底层的完全控制。就像从「用现成 agent」切换到「自己接管底层」，平台不再兜底，全你自己处理。

**prebuild 后你的世界变了（你朋友正在经历）**：
1. **要自己装原生环境**：之前 Expo 帮你省的 JDK、Android SDK、Xcode，现在全要自己装、自己配（回到本篇前面讲的那些）。这就是 prebuild 后突然要折腾一堆环境的根源。
2. **不能用 Expo Go 预览了**：它不支持自定义原生代码。改用模拟器/真机直接跑（`npx expo run:android` / `npx expo run:ios`）。
3. **多了 `android/` 和 `ios/` 文件夹要维护**：原生项目，偶尔要改里面的配置，出问题也常出在这。
4. **仍能用 Expo 的 JS 层包**：Expo SDK、各种 `expo-xxx` 包照常用，prebuild 不是抛弃 Expo 全部，只是不再让它托管原生层。
5. **升级 Expo SDK 更麻烦**：要合并原生项目的改动，不像托管模式一条命令搞定。

> 你朋友已经在原生项目上开发了，就按这条路线走——AI 会按 prebuild 后的方式操作（比如用 `npx expo run:android` 而不是 Expo Go）。原生层报错（红字提到 android/ios、gradle、xcodebuild）是这阶段的常态，别慌，贴给 AI 即可。

### Metro（Metro Bundler）

**大白话**：RN 的**打包器 / 翻译官**。

- 你写的 JS 代码，手机**看不懂**，得有个东西翻译打包成手机能跑的格式——这就是 Metro 干的活。
- 开发时它会**一直在后台跑**（一个终端窗口常驻），你每次改代码保存，它就重新打包、推到手机/模拟器上，实现「**改完立刻看到效果**」（叫**热重载 / 快刷新**，见下）。

**要点**：Metro 是个**实时翻译 + 推送**的中间人。你写的是 JS（手机看不懂），它实时翻译成手机能跑的格式并推过去。开发时它常驻后台，你每改一次它就重新翻译推一次。

> 你什么时候碰到：启动项目后，会有一个终端一直开着、显示 Metro 的画面（一个二维码 + 一堆文字）。**这个窗口别关**，关了 App 就没法热刷新了。

---

### 热重载 / 快刷新（Hot Reload / Fast Refresh）

**大白话**：你改完代码保存，**手机上的 App 几乎立刻变成新样子**，不用关掉重开。

- 这是 Metro 在背后推过去的。
- 偶尔会失灵（改了某些深层东西），那时按一下 `r` 重新加载，或重启 Metro 即可。

**要点**：就是「**改了立刻看到效果，不用整个重启**」。开发时最爽的体验就是它——改一行、存一下，手机上立刻变样。偶尔失灵重启一下就好。

> 你什么时候碰到：AI 说「保存一下看看效果」「热重载没生效，重启 Metro」时。

---

## 第六组：跟「代码管理」有关的

### 依赖（Dependency）/ node_modules

- **依赖**：你的项目**依赖的那些别人写好的包**。比如你用了一个图表库，它就是你的依赖。
- 装依赖的命令：`npm install`（照着项目里的 `package.json` 清单装）。
- **node_modules**：装完依赖后**自动生成的一个文件夹**，里面塞满了下载来的所有代码包。

**重要提醒**：
- node_modules **又大又多**（动不动几万个文件、几百 MB），**别手动改里面的东西**，也别想着上传到 git（下面讲）。它是自动管理的，删了能用 `npm install` 重新装回来。
- 看到这个文件夹塞满东西**别慌**，那是正常的。

**要点**：依赖就是你项目「**要调用的那些现成能力包**」（接上面说的）；node_modules 是存放这些能力包的**地方**，又大又多但自动管理——别手动改、别传 git（项目里会自动排除它），删了能用 `npm install` 重新装回来。

> 你什么时候碰到：AI 说「装一下依赖」「node_modules 没装」时。

---

### git / 仓库（Repository）/ GitHub

- **git**：代码的**版本存档系统**。每次提交（commit）都是一个存档点，改坏了能**随时回退**到之前的状态。
- **仓库（Repository，简称 repo）**：用 git 管理的一个项目文件夹。
- **GitHub**：放 git 仓库的**网站 / 网盘**，可以把代码传上去备份、和别人协作。

**类比**：git 像游戏的**存档系统**——每打完一关存一次档（提交一次 commit），改崩了能读档回到上一关。GitHub 像**代码的网盘**，把项目传上去，能备份、能和别人协作、换台电脑也能拉下来继续。

> 你什么时候碰到：AI 说「提交一下」「git commit」「推到 GitHub」时。
> **强烈建议**：每完成一个小功能就让 AI 帮你提交一次（你只要说「帮我提交当前进度」）。这样改崩了能回退，这是你最重要的救命稻草。

---

### 构建 / 编译 / 打包（Build / Compile / Bundle）

**大白话**：把你写的**源代码**，转换成手机能**安装运行的最终 App**（`.apk` 给安卓，`.ipa` 给 iOS）。

- **开发时**：Metro 实时编译，让你边写边看（dev 模式）。
- **发布时**：要打个完整包出来，安装到手机或上传到应用商店（release 模式）。

**要点**：源代码是「图纸」，打包是「**把图纸变成能交付的成品**」。开发时 Metro 实时编译让你边写边看；要上线了，才正式打个完整的安装包出来，装到手机上、或传到应用商店给用户下载。

> 你什么时候碰到：AI 说「打个 release 包」「构建安卓安装包」「iOS 打包上传」时。这是最后上线阶段的事，前期开发用不到。

---

## 装环境大概是什么顺序（给你个全景）

不用记，心里有个数就行，AI 会一步步带你走：

1. **装 Node**（带 npm）→ 万物的基础
2. **装 VS Code** → 写代码的地方
3. **建项目**：`npx create-expo-app myApp`（用 Expo，省心）
4. （如果要碰安卓）**装 Android Studio + JDK** → 用来开安卓模拟器
5. （如果是 Mac 且要碰 iOS）**装 Xcode** → 用来开 iPhone 模拟器
6. 跑起来 → 改代码 → 看效果 → 提交 git → 循环
7. （要上线时）**打包** → 上架

> 用 Expo **托管模式**的话，1-3 步就能先在手机上看到东西了，4-5 可以晚点再弄。**先把东西跑起来**，别一上来就配全套环境配到怀疑人生。
>
> ⚠️ **但你朋友已经 prebuild 了**：prebuild 后没有「晚点再弄」的待遇——第 4、5 步（装 Android Studio/JDK/Xcode）是**必须**的，不装原生环境就跑不起来。所以你现在确实得把这些装齐，这是 prebuild 的代价（见上面 prebuild 那节）。
