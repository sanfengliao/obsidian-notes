## 1. 包管理器那点事：npm / yarn / pnpm + 锁文件

00a 讲了 npm 是「装包的工具」。但你还会碰到 **yarn**、**pnpm**——它们和 npm 是**同类工具**，干的活一模一样（都是装包），只是不同团队的实现，各有各的小优势（pnpm 快、省空间；yarn 老牌稳定）。

**你要知道的就三点：**

1. **AI 给的命令可能是任一家的**，看懂即可，本质一样：
   - npm：`npm install xxx` / `npm install` / `npm run start`
   - yarn：`yarn add xxx` / `yarn` / `yarn start`
   - pnpm：`pnpm add xxx` / `pnpm install` / `pnpm start`
   - 别被不同写法吓到，都是「装包 / 跑脚本」。
2. **一个项目只用其中一个**。看项目根目录有哪个**锁文件**，就知道它用哪家：
   - `package-lock.json` → npm
   - `yarn.lock` → yarn
   - `pnpm-lock.yaml` → pnpm
3. **照着原项目用的那家来**，别混用。AI 会告诉你用哪个，你跟着敲就行。

### 锁文件（lock file）—— 重要

**大白话**：`package.json` 只写了「我要某个包」，但没钉死确切版本；**锁文件把每个包的确切版本号全钉死**，这样换台电脑、或上线打包时，装出来的依赖**完全一样**，不会因为某个包悄悄更新了版本而出 bug。

- **node_modules 不提交 git，但锁文件必须提交**（00a 说过 node_modules 别传，锁文件正好相反，要传）。
- 类比：锁文件像把「这次用到的每个 skill 的**确切版本**」存档钉死。换台机器照着存档装，出来一模一样——不然同一份代码，你电脑能跑、别人电脑/服务器跑不起来，因为版本对不上。锁文件就是消除这种「我这边好好的啊」。

> 你什么时候碰到：AI 说「提交一下 lock 文件」「装包前先拉一下锁文件」时。看到那三个锁文件之一，知道是干嘛的就行。

## 2. Node 版本管理器：nvm（头号报错源）

**大白话**：一台电脑可能要装**好几个不同版本的 Node**（项目 A 要 Node 18，项目 B 要 Node 20）。**nvm** 就是让你装多个版本、按项目切换的工具。（同类还有 fnm、volta，用法类似。）

**为什么要知道它**：**Node 版本不对，是新手最常踩、最诡异的坑**——很多莫名其妙的报错，查半天最后发现是 Node 太老或太新。AI 排错排到一半常会问「你 Node 版本多少」，就是这个原因。

常见命令（用到再查）：
- `nvm install 20` —— 装 Node 20
- `nvm use 20` —— 切到 Node 20
- `nvm ls` —— 看装了哪些版本

**类比**：给不同项目配不同 Node 版本，像给不同任务选不同模型——有的任务用 Claude 顺手、有的非得 GPT 不可。nvm 就是让你在一台机器上**装好几套、按需切换**，别被「全局只能装一个」卡住。

> **一开始的建议**：别折腾。装一个 **LTS 版**（Long Term Support，长期支持版，最稳，当前是 Node 20 LTS）就够大多数情况。真碰到版本报错了，再让 AI 帮你上 nvm 切版本。别一上来就给自己加戏。

## 3. 完整开发循环：从 0 到跑起来，再日常迭代

把流程串一遍，你心里就有数了。前几步是「一次性」的，后面是「反复循环」。

### 一次性：搭起来

```bash
npx create-expo-app myApp   # 1. 建项目（临时拉工具建个壳子）
cd myApp                     # 2. 进项目文件夹（cd = 进入文件夹）
npm install                  # 3. 装依赖（照清单把所有包装上）
npx expo prebuild            # 4. 生成原生项目（android/ 和 ios/ 文件夹）—— 你朋友已做过这步
npx expo run:android         # 5. 编译 + 装到安卓模拟器/真机 + 启动 Metro
                             #    （iOS 用 npx expo run:ios，需 Mac + Xcode）
```

- `cd myApp` 这步新手常卡——**终端得先进到项目文件夹里**，后面的命令才能找到项目。`cd` = change directory，换文件夹。
- 第 3 步如果用刚建的项目，依赖已自动装好，可跳过；**如果是 clone 别人的项目，必跑 `npm install`**。
- 第 5 步**第一次会比较慢**（要编译整个原生项目，几分钟），之后改 JS 就快了。你朋友项目已经 prebuild 过，平时直接从第 5 步开始跑即可。

### 预览：看效果

prebuild 后**不能用 Expo Go**，是直接编译装到设备上：
- `npx expo run:android` → 编译后装到安卓模拟器或真机
- `npx expo run:ios` → 装到 iOS 模拟器或真机（需 Mac + Xcode）
- 编译完成会自动启动 Metro，App 在设备上打开。
- 想在**真机**上跑：安卓插数据线（开 USB 调试），iOS 用 Xcode 配合签名。

### 日常迭代：改 → 看 → 提交（循环）

1. 在 **VS Code** 里改代码，`Cmd+S`（Mac）/ `Ctrl+S`（Win）保存。
2. **Metro 自动热刷新**，手机上立刻变样（见 [[01-最基础的工具与环境术语]] 的「热重载」）。
3. 效果对了，就**提交一个存档点**：跟 AI 说「帮我提交当前进度」，或自己敲：
   ```bash
   git add .
   git commit -m "加好了登录页"
   ```
4. 回到第 1 步，继续改下一个功能。

> ⚠️ 上面是**改 JS 代码**的循环，靠热刷新，很快。但如果**改了原生层**（`android/`、`ios/` 里的配置，或装了需要原生编译的包），热刷新不够，要重新 `npx expo run:android` 编译一次才生效。

**心法**：**小步快跑**——改一小块、看效果、没问题就提交、再改下一块。别攒一大堆改动才看效果，出错了根本不知道是哪步引入的。

## 4. 调试：出问题怎么查

新手最慌的就是「跑起来一片红 / 不对劲，不知道哪儿错了」。几个层次：

### 第一招：console.log（最朴素、最常用）

**大白话**：在代码里加一句 `console.log(某变量)`，程序跑到这行时，会**把那个变量的值打印出来**，你就能看到它到底是多少。

```js
const result = calculateSomething()
console.log("result 是:", result)   // 跑到这里会打印 result 的值
```

**类比**：你不知道程序跑到哪、中间值是啥，加句 `console.log` 就是**让程序把中间过程「说出来」给你看**——就像让 agent 把思考过程（show its work / 思维链）吐出来，好定位它到底哪一步算错了。变量值不对，往往就是 bug 的线索。

- 打印的输出在哪？**Metro 那个终端窗口**里会显示，去找你打印的文字。
- 查完 bug 别忘了删掉（或注释掉）这句，别留一堆调试打印。

### 第二招：看报错信息本身

- **手机红屏 / 终端红字**：别慌，**红字本身就告诉你哪儿错了**。虽然一坨英文，但里面通常有文件名、行号、一句话原因。
- **把整段红字复制给 AI**，问「这个报错什么意思、怎么修」。这是最快路径。
- 别只看第一行就猜，**整段**贴给 AI，它需要完整上下文。

### 第三招：调试工具（进阶，知道有这东西就行）

- **React Native Debugger** / **Flipper**：更专业的调试器，能打断点、一步步跑、看变量。AI 偶尔会提，前期用 `console.log` 就够了，不用学。
- **Chrome DevTools**：也能连上 RN 调试（RN 的 JS 跑在浏览器内核的调试协议上）。

> 前期你就靠 **console.log + 把报错贴给 AI** 两招，能解决 90% 的问题。进阶工具等真需要再说。

## 5. 代码规范工具：ESLint / Prettier（AI 帮你配，你认识就行）

这两个 AI 一般会在建项目时帮你配好，你看到它们的痕迹要知道是啥：

### ESLint —— 检查代码有没有问题

**大白话**：检查你代码写没写错、规不规范的工具。在 VS Code 里，它会在有问题的地方画**红色 / 黄色波浪线**，鼠标悬停看提示。

**类比**：像给代码配了个**自动纠错**——你哪写得不规范、可能有 bug，它标出来提醒你。有点像给 agent 设的「输出规则 / 约束」，违反了就提醒。看到红波浪线别慌，那是它在帮你抓潜在问题，复制提示给 AI 问怎么修即可。

### Prettier —— 自动排版

**大白话**：自动把代码**排版整齐**（缩进、换行、引号风格），你不用手动调格式。一般设成「保存时自动格式化」，所以你按保存会发现代码自己变整齐了——那就是 Prettier 在干活。

> 这俩是**帮你省心的**，不是给你添堵的。看到波浪线 / 代码自动排版别紧张，是工具在帮你。报错复制给 AI，让它解释。

## 6. TypeScript 配置：tsconfig.json（认识一下）

用 TS 的项目根目录会有个 `tsconfig.json`，是 **TypeScript 的配置文件**——告诉 TS 编译器一些规则（比如编译成哪个版本的 JS、哪些文件夹要检查、严格程度等）。

- **你基本不用手动改它**，AI 会管。
- 知道它是「TS 的设置文件」就行，AI 说「改一下 tsconfig」「这个 tsconfig 配置不对」时，你知道在说哪个文件。

## 7. 环境排错心法（新手最常遇到的 5 种）

遇到报错别慌，按这个顺序排查，大概率命中：

1. **`command not found`（或「不是内部或外部命令」）**
   → 工具没装，或 PATH 没配好。回 [[01-最基础的工具与环境术语]] 看 PATH。最常见是装了 node 但终端找不到。

2. **诡异的报错、莫名跑不起来**
   → **先怀疑 Node 版本**。终端敲 `node -v` 看版本，太老（低于 18）或太新都可能出问题。用 nvm 切到 LTS 版（见本文第 2 节）。

3. **端口被占用**（报错提到 `EADDRINUSE` 或 `port 8081`）
   → 上次的 Metro 没关干净，端口还占着。关掉旧 Metro 窗口，或重启电脑最省心。

4. **依赖出问题**（报错提到某个包、`module not found`）
   → 删掉重装最干净：
   ```bash
   rm -rf node_modules        # 删掉整个依赖文件夹
   npm install                # 重新装一遍
   ```
   （Windows 删除命令不一样，跟 AI 说「帮我删 node_modules 重装」它给你对应命令。）

5. **Metro 抽风 / 热刷新不灵**
   → 重启 Metro（关掉那个窗口，重新 `npx expo start`）。还不行就**清缓存**：`npx expo start -c`（`-c` = clear cache）。

### 通用心法

- **把完整报错贴给 AI**，比你自己猜快十倍。AI 排错最需要的就是完整错误信息。
- **先怀疑版本和 PATH**——这两个是万恶之源，占了新手报错的大半。
- **删掉重装 / 清缓存**是万能重启——很多玄学问题删 node_modules 重装、或清 Metro 缓存就好了，别死磕。
- **改不动就回退**：用 git 回到上一个能跑的存档点（说「帮我回到上一个提交」），再重新来。这就是 00a 让你勤提交的原因。

## 一张图：日常开发的心智模型

```
建项目(一次性) → 进目录 → 装依赖 → 启动 Metro
                                        ↓
                                  预览(模拟器/真机)
                                        ↓
        ┌──────── 改代码(VS Code) ←─────┘
        ↓                                  
   保存 → Metro 热刷新 → 看效果                
        ↓                                  
   对了 → git 提交存档 → 回到「改代码」继续
   错了 → console.log / 贴报错给 AI → 修 → 回到「看效果」
```

记住：**小步快跑、勤提交、报错贴全**。这三条能让你的开发体验从「怀疑人生」变成「还挺顺」。
