# 00a · Python 最基础的工具与环境术语（先看这篇）

> 这是写给「完全没碰过编程、想用 AI 帮忙写 Python」的人的。
>
> 这篇以 **Windows** 为主讲解，Mac 的命令差异会顺带注明。Windows 有几个 Mac 没有的专属坑（微软商店、PowerShell 脚本限制），本篇都会提到。
>
> 你要做的第一件事不是写代码，而是**装一堆东西、配环境**。装的时候会冒出来一堆词——Python、解释器、pip、虚拟环境、conda、Jupyter……这篇就是给你解释这些词是什么、为什么要装、装了干嘛用。
>
> 看完这篇，AI 让你「打开终端」「装个 Python」「配一下 PATH」「建个虚拟环境」「pip install 一下」时，你不会一脸懵。
>
> *注：下面有些地方用你熟悉的「大模型 / 对话」来类比，方便理解；但只在**真能对得上、且你作为普通使用者就懂**的地方用，对不上的就老老实实讲大白话，不硬套。*

---

## 第一组：跟「打字发指令」有关的

### 命令行 / 终端（Terminal / Command Line / Shell）

**大白话**：一个**黑底白字、靠打字发指令**的窗口。平时你用鼠标点来点去，在终端里是**打字下命令**。

- **Windows** 上叫「命令提示符」或「PowerShell」，现在更推荐用微软官方的 **Windows Terminal**（一个更好用的终端窗口，能开标签页）。Mac 上叫「终端 (Terminal)」。
- AI 经常说「在终端里运行 xxx」，意思就是：打开这个窗口，把那行命令敲进去，回车。
- 💡 **对 AI 更友好（可选）**：Windows 自带命令和 AI 常给的不太一样（比如列文件，Windows 是 `dir`，Linux/Mac 是 `ls`）。想更顺滑，可以装 **WSL**（Windows 官方的 Linux 子系统）或 **Git Bash**，这样 Windows Terminal 里就能直接敲 Linux 命令，AI 给的命令基本不用改。不是必须，但装上和 AI 协作更省心。


> 你什么时候碰到：几乎每次操作都离不开它。AI 给你的命令（像 `python xxx.py`、`pip install numpy`）都要在这里敲。

---

### 路径（Path / 路径）

**大白话**：一个文件或文件夹在电脑里的**地址**。

- **绝对路径**：从硬盘根开始，完整地址。像 `C:\Users\你\Desktop\myScript`（Windows）或 `/Users/你/Desktop/myScript`（Mac）。
- **相对路径**：相对于「你当前在哪个文件夹」的地址。Windows 用 `.\` 表示当前文件夹，像 `.\data\xxx.csv` 表示「当前文件夹里的 data 文件夹里的 xxx.csv」（Mac/Linux 用 `./`，意思一样）。

**类比**：绝对路径像「**北京市海淀区中关村大街 1 号**」——从国家往下，完整地址，谁都找得到。相对路径像「**隔壁那家便利店**」——得先知道**你现在站在哪**，才知道这便利店是哪家。

> 你什么时候碰到：AI 说「进入项目目录」「这个文件在 `src/` 下」时。看不懂路径就不知道文件在哪。

---

### 环境变量 / PATH（最常让你卡住的东西）

**大白话**：电脑有一些**全局的设置项**，其中最重要的一个就叫 **PATH**。

- PATH 告诉电脑：「**当我在终端里敲一个命令时，去哪些文件夹里找对应的程序**」。
- 你装了 Python，但终端里敲 `python` 却提示「command not found」——**十有八九就是 Python 没被加进 PATH**，电脑不知道去哪找它。

> 你什么时候碰到：装完 Python 后，终端报「不是内部或外部命令，也不是可运行的程序或批处理文件」或「command not found」。这时跟 AI 说「我装了 Python 但终端找不到」，AI 会让你「配一下 PATH」。
> 好消息：**在 Windows 装 Python 时，安装向导第一屏一定要勾选「Add python.exe to PATH」（把 Python 加进 PATH）**，勾了基本就不会碰到这个问题。这个词你得认识。

---

## 第二组：跟「Python 本体」有关的

### Python 语言 + 解释器（Interpreter）

**大白话**：Python 是一门**编程语言**（你写代码用的那套语法规则），而**解释器**是**一个让电脑能执行 Python 代码的程序**——你常说的「装 Python」，装的主要就是这个解释器。

- 你写的代码是**纯文本**（存在 `.py` 文件里），电脑 CPU 听不懂这种语法，得有个东西把它**逐行翻译**成电脑能执行的指令，这个「翻译官」就是解释器。
- 所以一句话：**装了 Python = 装了解释器** = 电脑现在能跑 Python 代码了。

> 你什么时候碰到：搭环境第一步就是装 Python。AI 说「确认装了 Python」「Python 版本多少」时，就是它。

---

### Python 版本（3.x，别碰 Python 2）

**大白话**：Python 有好多版本号，像 `3.12`、`3.11`、`3.10`。

- **只要记一条：用 Python 3（`3.x`）**。老旧的 Python 2 早在 2020 年就停止维护了，网上看到 Python 2 的教程直接跳过。
- 版本号第一位是「3」就够了，具体小版本（3.10 还是 3.12）差别不大，**AI 让你装哪个就装哪个**。
- 装**最新稳定版**一般没错，别装太老的。

> 你什么时候碰到：AI 说「确认一下 Python 版本」「python --version」时。终端里显示的那个 `3.12.x` 就是版本号。

> 💡 **Windows 装 Python 的两个小提醒**（装的时候顺手做，省得以后麻烦）：
> 1. **装到 C 盘以外的盘**：安装向导里选「自定义安装」，把安装位置改到别的盘（比如 `D:\Python`）。不然以后 `pip install` 的全局包会跟着 Python 装进 C 盘，越攒越多，把系统盘塞满。（小补充：pip 的下载缓存仍默认在 C 盘，跟 Python 装哪没关系，那是缓存、不是装进 Python 的包；真在意可以让 AI 帮你把缓存也挪走。）
> 2. **安装路径别带中文**：路径里只用英文，像 `D:\Python`，别出现中文（比如 `D:\软件\Python`）。Python 自己一般没事，但有些第三方库、打包工具（PyInstaller）碰到中文路径会报错。

---

### `python` / `python3` / `py`（怎么叫它）

**大白话**：在终端里敲什么命令来启动 Python，不同系统不一样。

- **Windows**：一般敲 **`python`** 就行；装完官方 Python 后，**`py`** 这个命令也一定可用（Windows 专门的启动器，装好就自动配好了），两个都行。
- **Mac / Linux**：常要敲 **`python3`**（而不是 `python`），因为系统自己内置的 `python` 可能是别的东西。
- 判断标准很简单：**敲了之后出现 `>>>`（Python 交互提示符），就说明成功启动了**。

**要点**：不用纠结命令是 `python` 还是 `py`——**AI 给你哪个就用哪个**，报错了它会告诉你怎么改。关键是认得出启动成功的样子（`>>>`）。

> 你什么时候碰到：AI 说「跑一下：python xxx.py」「用 py 试试」时。都指同一个 Python，只是叫法不同。
>
> ⚠️ **Windows 一个经典坑**：如果敲 `python` 后**弹出了微软商店（Microsoft Store）**，说明电脑上还没装 Python（Windows 拿商店当「假入口」）。这时**别从商店装**，去官网 python.org 下载安装包，装的时候勾选「Add python.exe to PATH」。

---

### .py 文件 / 脚本（Script）

**大白话**：**把 Python 代码存成后缀是 `.py` 的文本文件**，这个文件就叫一个「脚本」。要用的时候，终端敲 `python xxx.py` 一次性把它跑完。

- 你平时写的代码，基本都是存进 `.py` 文件里（而不是在终端里现场手敲）。
- 跑脚本：`python xxx.py`（在 xxx.py 所在目录，或给全路径）。


> 你什么时候碰到：AI 说「把这段代码存成 `xxx.py`」「运行一下 `python xxx.py`」时。

---

### REPL / 交互模式（那个 `>>>`）

**大白话**：在终端里直接敲 `python`（不加任何文件名），会进入一个 **`>>>` 开头的对话界面**，你敲一行、它执行一行。这个模式叫 REPL 或「交互模式」。

- 适合**试小代码**：临时算个数、看看某个函数怎么用。
- 退出：敲 `exit()`，或按 `Ctrl+Z` 再回车（Windows）/ `Ctrl+D`（Mac）。

**类比**：REPL 像跟 AI **一句一句对话**——你说一句它回一句，适合快速试探；脚本像给 AI **一整段任务**让它一次性执行，适合正经干活。正式写程序用脚本，临时验证用 REPL。

> 你什么时候碰到：AI 说「在终端里敲 python 进入交互模式试一下」「试试这个表达式」时。

---

### 解释型 vs 编译型（一句话搞懂）

**大白话**：有些语言（像 **C**）写完要**先整体编译**成一个电脑能直接跑的文件，才能运行；Python 是**解释型**的——不需要这一步，写完直接交给解释器跑。（Java 是中间派：编译出来的是中间码，还得靠 JVM 再翻译一遍才能跑，不是「编译完就能直接跑」。）

- 好处：**改完立刻能跑**，开发很爽，也不用担心「编译失败」。
- 代价：**单独一个 `.py` 文件不能直接发给别人双击运行**（别人也得装 Python）。想做成双击就能跑的程序，得用「打包」工具（见后面）。

**要点**：Python「改完就能跑」很省心，但要注意「别人没装 Python 就跑不了你的 .py」这件事——要给别人用，得打包。

> 你什么时候碰到：AI 说「直接 python 跑，不用编译」「用 PyInstaller 打包成 exe」时。

---

## 第三组：跟「装包、管依赖、管环境」有关的

### 包 / 库 / 模块（Package / Library / Module）

**大白话**：别人写好的一段现成功能代码，你**下载来直接用**，省得自己造轮子。

- **模块（module）**：最小单位，通常一个 `.py` 文件就是一个小模块。
- **包（package）**：一组模块打包放在一起的文件夹。
- **库（library）**：泛称，泛指别人写好供你调用的现成代码，可以是一个或一堆包。比如 `requests`（发网络请求）、`pandas`（处理表格数据）都是著名的库。

**类比**：这类「现成代码」就像 AI 里的「skill（能力包）」——别人把某个能力做好、打包好，你 `pip install` 装进来，随时调用，不用自己从头造。你想要某个功能（处理表格数据），就去装一个对应的库，这个能力就成了你项目的一部分。

> 你什么时候碰到：AI 说「需要装个 xxx 库」「import numpy」时。`import` 就是「把这个库引进来用」的意思。

---

### pip

**大白话**：Python 自带的**「代码包商店」**。别人写好的库，你用 pip 下载来用。

- 常见命令：
  - `pip install xxx` —— 装一个库（也写作 `pip3 install xxx`）
  - `pip install -r requirements.txt` —— 照着项目清单一次性装好所有库（见下面 requirements.txt）
  - `pip list` —— 看看现在装了哪些库
- 新一点的 Python 推荐用 **`python -m pip install xxx`** 的写法（更稳，避免命令冲突），效果和 `pip install xxx` 一样。

**类比**：pip 上每个「库」就像一个**封装好的 skill（能力包）**——别人把某个能力做好了、打包好，拿来就能用，省得自己从头造。你想要某个功能，就 `pip install` 把它装进来，这个能力就成了你项目的一部分，随时能调用。

> 💡 **国内装包太慢？** pip 默认去国外的 PyPI 下载，国内可能很慢甚至超时。最省事的办法是让 AI 帮你配一下**国内镜像源**（最常见的是「清华源」/「阿里源」）。跟 AI 说「pip 太慢，帮我换个清华源」就行，它会给你配好。

> 你什么时候碰到：AI 说「装个依赖」「pip install 一下」时。这是你敲得最多的命令之一。

---

### PyPI

**大白话**：pip 背后那个**存着所有库的「总仓库」**（Python Package Index 的缩写）。`pip install xxx` 就是从 PyPI 上把 xxx 下载下来。

**类比**：PyPI 就是 pip 的「**应用商店 / 库房**」，pip 是「去库房取货的搬运工」。你不直接跟 PyPI 打交道，但要装的东西都是从那儿来的。

> 你什么时候碰到：基本不用直接碰它，知道「pip 装的东西都是从 PyPI 来的」就够了。

---

### 虚拟环境（venv）——新手最该养成的习惯

**大白话**：虚拟环境是给**每一个项目单独开一个「环境」**。这个环境用哪个版本的 Python、装哪些库，都由项目自己说了算，跟电脑上其他项目互不干扰。

**它解决什么问题（为什么必须）**：
- **管理库版本**：项目 A 要用 `pandas 1.x`，项目 B 要用 `pandas 2.x`——都装在全局会打架（装成 2.x，项目 A 的代码就崩了）。有了虚拟环境，A 的环境里装 1.x、B 的环境里装 2.x，互不干扰。
- **限制 / 隔离 Python 版本**：虚拟环境是「绑定」创建它时用的那个 Python 版本。电脑上装了多个 Python（比如 3.10、3.12）时，可以给项目 A 建一个 3.10 的环境、项目 B 建一个 3.12 的环境，A 升级 Python 版本也不会影响 B。
- **环境干净、可复现**：每个项目装了哪些包，都清清楚楚记在自己的环境里（配合 requirements.txt）。换电脑、别人接手你的项目，照着清单装一遍就能跑。

**怎么建（在项目文件夹里敲）**：
- **建**：`python -m venv .venv`（Windows 用 `python`；Mac/Linux 用 `python3`。生成一个叫 `.venv` 的隐藏文件夹）
- **激活**：Windows 敲 `.venv\Scripts\activate`，Mac/Linux 敲 `source .venv/bin/activate`（激活后终端前面会多出 `(.venv)` 字样）
- **退出**：敲 `deactivate`

> 你什么时候碰到：AI 说「建个虚拟环境」「激活虚拟环境」时。**这是 AI 默认会做的事**（好习惯）。你看到终端前面出现 `(.venv)`，就说明现在在这个项目自己的环境里。
> 注意：`.venv` 文件夹不要手动去动，也不要传到 git（项目会自动忽略它）。
>
> ⚠️ **Windows PowerShell 专属坑**：用 PowerShell 激活时，可能报「因为在此系统上禁止运行脚本」——这是 Windows 的安全限制。别自己乱试，把整段红字贴给 AI，它会让你跑一条 `Set-ExecutionPolicy` 命令放开限制，就好了。

---

### requirements.txt / pyproject.toml（项目的「依赖清单」）

**大白话**：项目里用来**记录「这个项目需要哪些库、什么版本」**的文件。

- **requirements.txt**：最传统的清单，一行一个库名（如 `numpy`、`pandas==2.0.0`）。看到别人的项目有这个文件，就 `pip install -r requirements.txt` 照着装。
- **pyproject.toml**：更现代、更全面的配置文件（新版 Python 项目越来越多用它），里面除了依赖，还能记项目信息。

> 你什么时候碰到：AI 说「把装过的库写进 requirements.txt」「照着 requirements.txt 装依赖」时。这是项目可移植的关键。

---

### uv（新一代「包 + 环境 + Python 版本」三合一）

**大白话**：一个比较新的工具，把之前学的三样东西**合并成了一个**：
- **pip 的事**——装库、管依赖；
- **venv 的事**——建虚拟环境；
- **pyenv 的事**——装 / 切换 Python 版本（pyenv 就是专门管 Python 版本的工具，之前没单独讲）。

它用 Rust 写的，**特别快**，这两年越来越流行，很多新项目（尤其是 AI 相关）默认就用它。

**常用命令对照**（看到 `uv` 开头的命令别慌，跟 pip / venv 是一个意思）：

| 原来的做法 | 用 uv |
|-----------|-------|
| 建虚拟环境 `python -m venv .venv` | `uv venv`（在当前文件夹建） |
| 装库 `pip install xxx` | `uv add xxx`（还会自动记进 pyproject.toml） |
| 照清单装齐 `pip install -r requirements.txt` | 老项目：`uv pip install -r requirements.txt`；新项目：`uv sync`（照着 pyproject.toml / uv.lock） |
| 跑脚本 `python xxx.py` | `uv run xxx.py`（自动建 / 用环境，不用手动激活） |
| 装某个 Python 版本（原本要 pyenv 等工具） | `uv python install 3.12` |

**要点**：
- `uv` 把「建环境 + 激活 + 装库 + 跑代码」串成**一条龙**，很多步骤自动完成——比如 `uv run` 会自己找到（没有就创建）环境，你**不用手动激活**。
- **环境已激活时，直接 `python xxx.py` 也能跑**：`uv run` 是省事的写法；如果你已经激活了 uv 建的环境（Windows 敲 `.venv\Scripts\activate`），它就是个普通虚拟环境，直接 `python xxx.py` 跑脚本一样生效，不一定要 `uv run`。
- **老项目也兼容**：以前用 requirements.txt 的老项目，直接用 `uv pip install -r requirements.txt` 就能照常装，**不用**迁移成 pyproject.toml——uv 是 pip 的「即插即用」替代品。（注意：`uv sync` 是「项目模式」命令，**需要 pyproject.toml**，纯 requirements.txt 项目直接跑会报错；真想用 `uv sync`，先敲 `uv add -r requirements.txt` 把依赖导入 pyproject.toml，之后就能 sync 了。）
- 它用的是更现代的 **pyproject.toml** 作为项目清单（见上面那节），还会生成一个 `uv.lock` 锁文件记录精确版本。
- **Windows 怎么装**：让 AI 帮你装就行（常见是官网一条 PowerShell 命令，或 `pip install uv`，或 winget 装）。

> 你什么时候碰到：AI 说「用 uv 建环境」「uv add 装一下」「uv run 跑起来」时。
> **用 uv 还是传统的 pip/venv，效果一样，只是工具不同**——AI 用哪个你就跟哪个，报错整段贴给它即可。

---

### conda / Anaconda / Miniconda

**大白话**：另一套「装 Python + 管包 + 管环境」的工具，**数据科学（数据分析、机器学习）方向**特别流行。

- **Anaconda**：一个**全家桶**——装它等于同时装好 Python + 一堆数据科学常用库（numpy、pandas、matplotlib 等）+ conda 工具，开箱即用，但很大。
- **Miniconda**：Anaconda 的**精简版**，只有 Python + conda，要什么库自己再装。
- **conda**：里面的「包 + 环境管理器」，也能建虚拟环境（和 venv 干的事类似），还能管 Python 版本本身。

**怎么选**：**现在用得最多的是 uv**（见上面那节），**新老项目都能用 uv**——新项目用 pyproject.toml + `uv sync`，老项目用 `uv pip install -r requirements.txt` 照常装，都不用上 conda。**数据分析 / 机器学习也用 uv**：numpy、pandas、torch 这些科学计算库在 PyPI 上都有现成包，`uv` 装得又快又省事。conda 系（Anaconda / Miniconda）只在**少数特殊情况**才考虑：比如项目要处理 Python 之外的底层二进制依赖（某些 GPU 工具链），或者想开箱即用、不想一个个装科学计算库。拿不准就听 AI 的，AI 让你装哪个就装哪个。

> 你什么时候碰到：AI 说「装个 Anaconda」「用 conda create 建环境」时。这通常是数据科学方向的标配。

---

## 第四组：跟「写代码、跑代码的地方」有关的

### IDE / 编辑器 / VS Code / PyCharm

- **IDE**（集成开发环境）：写代码的**大本营软件**，集成了编辑、提示、报错、调试等功能。**PyCharm** 就是专门为 Python 出的知名 IDE。
- **编辑器**：更轻量的写代码工具。**VS Code** 是目前最流行的代码编辑器，装个 **Python 插件**后写 Python 体验很好。
- 你和 AI 主要在 VS Code 里看代码、改代码、跑代码。

**要点**：VS Code 就是你**写代码的主软件**。PyCharm 功能更专但更重，新手用 VS Code + Python 插件基本就够了，AI 也最熟 VS Code。

**VS Code 实操（新手必知）**：
- **打开项目**：`File → Open Folder`，选**整个项目文件夹**，别双击单个文件。
- **内置终端**：`Terminal → New Terminal`（快捷键是 Ctrl 加反引号键，反引号在 Tab 上方），跑 `python xxx.py`、`pip install` 都在这里敲。
- **保存**：`Ctrl+S`（Windows）/ `Cmd+S`（Mac）。改完一定保存再跑。
- **插件（扩展）**：左边栏方块图标，或 `Ctrl+Shift+X`，搜「Python」装官方插件（代码提示、报错都靠它）。

> 你什么时候碰到：AI 说「打开这个文件」「在 VS Code 里改一下」「在集成终端里跑」时。

---

### Jupyter Notebook（`.ipynb`）

**大白话**：一个在**浏览器里打开的「实验笔记本」**，页面是一格一格的单元格（cell），你可以**每一格写一小段代码、跑一下立刻看结果**，文字、代码、结果混在一页。

- 适合：数据分析、做实验、教学、逐步探索——边看中间结果边往下走。
- 怎么用：装了 jupyter 后，终端敲 `jupyter notebook`（或 `jupyter lab`）会自动打开浏览器页面。
- **VS Code 天然集成**：装了 Python 插件（自带 Jupyter 支持）后，也可以**直接在 VS Code 里打开 `.ipynb` 文件**，一格一格跑、结果就显示在格子下方，不用另开浏览器，更省事。
- **AI 配合也顺**：VS Code 里的 AI（Copilot / CodeBuddy 这类）对 notebook 支持得不错——你可以在格子里用大白话描述要什么，AI 直接生成代码；也能让 AI 解释某一格、改 bug、优化。数据分析 + AI 协作的场景，在 VS Code 里做 notebook 很顺手。
- 文件后缀是 `.ipynb`。

**类比**：Jupyter 像「**代码版的 Excel / 实验记录本**」——一格格写、一格格算，中间结果随时看，边做边记。而 `.py` 脚本更像「**正式交付的程序**」：从头到尾一次跑完。分析探索用 Notebook，正式功能写成 `.py`。

> 你什么时候碰到：AI 说「用 Jupyter 跑这个」「建个 notebook 试试」时。数据科学、AI 方向最常用它。

---

### 三种「跑 Python」的方式，一张表记住

| 方式 | 命令 / 入口 | 干什么用 |
|------|------------|---------|
| **交互模式 REPL** | 终端敲 `python`，进入 `>>>` | 试一两行小代码 |
| **脚本** | `python xxx.py` | 正式跑完一段完整程序 |
| **Notebook** | `jupyter notebook` | 边写边看结果，做分析 |

> 90% 的时候你用的是**脚本**（`.py`）。REPL 和 Notebook 是补充，知道存在即可。

## 第五组：跟「代码管理、发布成品」有关的

### git / 仓库（Repository）/ GitHub

- **git**：代码的**版本存档系统**。每次提交（commit）都是一个存档点，改坏了能**随时回退**到之前的状态。
- **仓库（Repository，简称 repo）**：用 git 管理的一个项目文件夹。
- **GitHub**：放 git 仓库的**网站 / 网盘**，可以把代码传上去备份、和别人协作。

**类比**：git 像游戏的**存档系统**——每打完一关存一次档（提交一次 commit），改崩了能读档回到上一关。GitHub 像**代码的网盘**，把项目传上去，能备份、能和别人协作、换台电脑也能拉下来继续。

> 你什么时候碰到：AI 说「提交一下」「git commit」「推到 GitHub」时。
> **强烈建议**：每完成一个小功能就让 AI 帮你提交一次。这样改崩了能回退，这是你最重要的救命稻草。

---

### 打包（PyInstaller / 生成 .exe）

**大白话**：把 `.py` 代码**做成一个别人双击就能跑的程序**（Windows 上通常是 `.exe`），别人不用装 Python 也能用。

- 常用工具：**PyInstaller**。命令大致是 `pyinstaller xxx.py`，它会生成一个 `dist` 文件夹，里面就是打包好的成品——Windows 上是一个 `.exe`，可以直接发给别人双击运行。
- 注意：打包出来的文件**比较大**（里面自带了一整个运行环境），而且只能**在同一类系统**上跑（Windows 打出来的 Windows 用，Mac 打出来的 Mac 用）。

**类比**：前面说过，跑 `.py` 像「开发模式」——得装了 Python（解释器）才能跑；**打包就是「发布正式版」**——把运行环境一起塞进一个文件，别人拿到就能用，像给 App 打一个安装包。

> 你什么时候碰到：AI 说「给你打包成 exe」「用 PyInstaller 打包」时。这是要把程序给别人用、或发布时的阶段，前期开发用不到。

## 装环境大概是什么顺序（给你个全景）

不用记，心里有个数就行，AI 会一步步带你走：

1. **装 Python**（3.x 最新稳定版，勾选「Add python.exe to PATH」；装到非 C 盘、路径别带中文见「Python 版本」一节的 💡）→ 让你**随时能敲 `python` 打开解释器 / 跑脚本**，这是基础
2. **装 uv**（见「第三组」的 uv 一节）→ 项目里管包、管环境、管 Python 版本更省事
3. **装 VS Code** + Python 插件 → 写代码的地方
4. **建项目**：`uv init`（在当前文件夹生成 pyproject.toml）
5. **装库**：`uv add xxx`（自动记进 pyproject.toml）
6. **写 `.py` 脚本** → `uv run xxx.py` 跑（环境自动建好、不用手动激活）→ 看效果 → 改 → 循环
7. **每完成一步提交 git** → 存档保命
8. （要给别人用时）**打包**成 exe / 可执行文件

> 如果接手的是**老项目**（用 requirements.txt / pip）：也能用 uv 的 pip 兼容模式 `uv pip install -r requirements.txt` 照常装（见 uv 一节）；或者干脆走传统流程（`python -m venv .venv` → `pip install`）。**AI 用 uv 还是传统 pip/venv，你就跟着它走，都能干活。**
>
> 如果是**数据分析 / AI 方向**：用 uv 也能做（numpy、pandas、torch 都有现成包，装得很快）；也有人习惯用 conda 系（Miniconda / Anaconda）+ Jupyter Notebook 来做。两条路都行，听 AI 的即可。
>
> ⚠️ **核心心法：先把最小的一步跑起来**（比如先让它打印出 Hello），别一上来就装全所有库配到怀疑人生。跑通一小步，再一步一步加。
